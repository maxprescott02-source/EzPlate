Addendum to the design package (§16–18). Everything here restyles mechanisms already shipped in prod — toast(), #syncBanner, the boot gate — nothing new is invented.

16 · Error & edge states

Prod's rule stands: a failed write is never quiet. The redesign keeps the shipped wording verbatim (it was fought for) and only restyles the vessels. Errors speak in words a chef reads — never a code, never jargon; every error offers exactly one action.

Sync pill · #syncBanner states

Loading latest data… Saving… Saved Offline — changes won't save Can't reach server — working offline

Lives in the header (desktop: right of the page title; mobile: under the top bar). ok auto-hides after its existing timeout; offline/error persist until resolved. Never repositioned per screen.

Toast · #toast, 2.2s, bottom-centre

Barramundi Fillet added Couldn't save plate: permission denied Couldn't save menu item — you're offline. It has NOT been saved.

Failure toasts get the 1px --bad border + icon; wording is prod's, unedited. Failure toasts hold 5s (not 2.2s) — a chef mid-service must have time to read "NOT been saved". Success stays 2.2s. No stacking: newest replaces.

Boot gate · error + retry

You're offline. EzPlate needs a connection to load your products, plates and menus.

Existing states kept as-is: loading message, the 4s patient swap ("Still loading — the first open after a break takes a little longer."), error with the one retry. Redesign centres it in the content column, chrome stays usable.

Invoice file failed

Couldn't read that file

It doesn't look like an invoice we can read. A photo or PDF from your supplier works best.

Replaces the file strip in the import modal; nothing below it renders. Says what to do, not what went wrong internally. The protected parser is untouched — this is presentation only.

17 · Tablet & breakpoints

One rule set, four widths. Tablet is mobile chrome with desktop room — bottom nav stays until 1024px (the shipped swap point), touch targets stay ≥44px throughout, and nothing ever scrolls horizontally.

< 768Phone. As Mobile States: single column, 16px gutters, bottom 5-tab nav, sticky builder footer, floating + button.
768–1023Tablet. Bottom nav kept. 24px gutters, content max 720px centred. Dashboard's What moved / Dig in go two-column; Menu renders the desktop table (it fits at 720); Builder keeps the stacked layout — the sticky cost panel needs ≥1120px.
≥ 1024Desktop. Sidebar shell (216px + max-1000px column) via the existing .side-brand swap. Hover states arm here only (@media (hover:hover)).
1120 · 1130Local wraps. Below 1120px the builder cost panel stacks under the docket; below 1130px the Menu filter toolbar wraps. These are the only per-screen breakpoints — add no others.

Café iPads live in this band, usually landscape (1024–1180px) — so an iPad landscape gets the full desktop shell, and portrait (768–834px) gets tablet. Both are first-class; test both orientations per batch.

18 · First run

A fresh database is genuinely empty now (seeding was removed on purpose). The empty states ARE the onboarding — no tour overlays, no walkthrough modals, no checklists that nag. Each empty screen states the one next step in chef words; the Dashboard shows the whole path.

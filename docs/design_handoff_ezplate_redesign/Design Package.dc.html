3 · Spacing & shape

Keep the current 4px scale: 4 · 8 · 12 · 16 · 20 · 24 · 32. Card seam stays 8px; page gutter 16px mobile, 40px desktop main column. Desktop shell: 216px sidebar + content column max 1000px.

Radii: 16px cards · 12px controls/inputs · 10px buttons in rows · 999px chips.

Row heights: dense list rows ~46px (11px vertical padding), action rows with sub-lines ~62px. Hairline 1px --border separators INSIDE one surface — no card-per-row. Dashed borders are reserved for the docket idiom.

10 · Navigation

Desktop (≥1024): 216px sidebar, items 14px/700, active = --accent-weak fill + accent text (the page's one standing accent). Theme + Settings pinned to the foot. No tagline anywhere in chrome.

Mobile (<1024): the existing 5-tab bottom bar, 56px hit targets, active in accent. Order and data-tab values unchanged (the naming inversion stays internal).

11 · Motion & interaction states

Keep the app's existing motion system verbatim — one easing family, three durations, nothing ad-hoc. Every interactive element defines all five states; none may be missing.

Durations/easing (unchanged): --t-fast .14s taps, hovers, chips · --t-med .22s dropdowns, rows, toasts · --t-slow .3s modals, panels · easing cubic-bezier(.2,.7,.3,1); the spring easing stays reserved for the two signature moments (AI panel arrival, invoice toast). All motion off under prefers-reduced-motion.

Per-component state table: rest · hover (--field fill on rows, darkened accent on primary) · pressed (translateY(1px), --t-fast) · focus-visible (2px accent ring, offset 2px, NEVER removed) · disabled (--field fill, --muted text, no pointer).

Optimistic updates: a save repaints instantly, the toast waits for the server (the app's existing rule — the wording never claims success before the write lands).

AI phrasing swap: templates render first; the Gemini phrasing cross-fades in at --t-med. It settles, never flashes.

14 · Loading

The boot gate and splash stay exactly as shipped (they are keyed to real data arrival). WITHIN a loaded app, a region that waits (AI phrasing, invoice referee) shows skeleton bars in its own layout — never a spinner in a card, never layout shift when content lands.

15 · Keyboard, focus & contrast

Keyboard (desktop): / focuses search on any list screen · Esc closes the top layer only · Enter on a focused row = the tap action · arrow keys scrub the trend chart (already shipped — keep). No shortcut chords; this is not a power tool.

Focus: every row-button, chip and control shows the 2px accent ring on :focus-visible. Dialogs trap focus and return it to the opener on close.

Contrast floors: --muted is legal only ≥12px AND for dispensable text (captions, units); anything the user must read to act uses --text2 or better. Semantic colours on dark must be used at their dark-mode values (already AA on --surface); never place --warn text on --warn-bg smaller than 13px bold.

Icons: one set — 24px viewBox, 2px stroke, round caps (the current nav icons define it). Theme toggles use the existing moon/sun SVG pair (24px viewBox, 2px stroke) — implemented in the mocks.

16 · Notes for the coding agent

· All tokens already exist in css/style.css — this package changes STRUCTURE, not palette. New tokens needed: none.

· Never rename identifiers, ids, data-tab values or storage keys; change only what a human reads.

· Small-caps eyebrows: max one per panel, section boundaries only. Row labels are gone — position + the fixed figure column carry the meaning.

· Figures: mono + tabular-nums, right-aligned in a fixed column, ≥ the row's word size. Colour on a figure is a judgement (target-anchored), never decoration.

· The builder's cost panel is position:sticky on desktop and becomes the sticky footer (total + Save together) on mobile.

· Visual changes remain surgical, one screen per batch, per the standing rule.

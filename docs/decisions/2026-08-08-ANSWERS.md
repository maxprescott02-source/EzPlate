### 1. Staging — a free second Supabase project

Max confirmed separately he does **not** need Supabase Pro ($25/month); the free tier is the plan.
**Still outstanding: the project ref.** Nothing can be built until it exists and lands in `.mcp.json`.
Known friction accepted at decision time: free projects pause after about a week idle, and staging will sit idle exactly that long between batches, so it will often need an unpause click.

### 2. The builder becomes a modal

Against the recommendation, which was to leave it a page and fix the dropdowns directly.
This is the answer to a question open since before v113 and it **unblocks the dropdown work**, which cannot sensibly be done twice — the positioning context changes with the builder.
Order is now fixed: **modal first, dropdowns second.**

### 3. No second reader beyond the pre-push agent

Against the recommendation, which was CodeRabbit (free, with a measured record here).
**Both blocked items are closed by this: CodeRabbit and GitHub Pro are decided NO. Do not re-propose either.**
The option Max chose was worded "the current pre-push review is enough", so the mandatory pre-push `code-review` agent **stays exactly as it is** — this declines an *additional* reader, it does not relax the existing rule.

Worth recording alongside, without re-litigating: on the day this was decided, that pre-push review caught a defect in a four-word change that would have silently discarded a plate's category edit, with the whole suite green and the change already driven in a browser.
So the reviewer Max kept is the one doing the work.

### 4. `menus` RLS fixed now

Against the recommendation, which was to wait for the multi-tenant gate.
Migration written: `supabase/migrations/20260808_menus_rls.sql`. **Not applied — migrations are applied by hand, by Max.**
It enables RLS and creates the same permissive `staff full access` policy its three closest siblings already carry, in **one transaction**, because the half-applied state shows an app with zero menus rather than raising an error.

### 5. Dashboard shows a dash — already true

Agreed with the recommendation, and **it needs no work: the app already does this.**
v97 fixed it (`computeAvgFoodCost` returns null, `verdictHtml` renders `—` plus "Nothing costed and priced yet"), and `tests/dash-persist.test.js:400` has pinned it since.
Reproduced 8 Aug 2026 in a real browser at 380px with zero menus and 14 history points: headline `—`, honest line, chart still drawn.
**The queue item was stale** — it described pre-v97 behaviour and survived the 7 Aug reconcile without being checked against the code.
Max's answer therefore confirms shipped behaviour rather than changing it, which is a good outcome: the behaviour now has an explicit owner's decision behind it, not just a bug fix.

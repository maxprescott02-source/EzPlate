# Parser eval fixtures

Every file here is INVENTED (no real cafe, supplier or account). They are regenerated by
`python3 tests/parser-corpus/make-fixtures.py`; edit that file, not these.

A case is `NAME.txt` plus `NAME.truth.json`.

- `NAME.txt` is what the APP sees: for a PDF, the output of `extractPdfText()` (one visual line per
  row, single spaces, page after page); for the paste box, the CSV. Produce the former from a real
  PDF with `spike/parser-audit/extract-pdf.mjs`, never with `pdftotext`, whose column order differs.
- `NAME.truth.json`:

```
{
  "style":   "one paragraph: columns, where qty sits, how packs are written, GST basis, oddities",
  "source":  "pdf" | "csv",
  "gst":     "ex" | "inc",            what the document's prices are
  "subtotal": 0, "gst_amount": 0, "total": 0,
  "lines": [ {
      "desc":  "human label",
      "match": "substring (case-insensitive) that identifies the parsed row's raw line",
      "qty": 3, "pack": "6x2kg", "unitPriceEx": 29.50, "per": "ctn", "lineTotal": 88.50,
      "accept": [ {"unit":"kg","price":2.4583}, {"unit":"ea","price":1.09} ],
                 every (unit, ex-GST price per stored unit) the app may store for this line;
                 an EMPTY list means "the only right answer is to ask" (needManual)
      "note":  "optional"
  } ],
  "exclude": [ "fuel levy", "total due" ]   substrings of lines that must not become priced rows
}
```

The runner (`tests/parser-corpus/run.js`) scores each truth line as right / noisy / silent-wrong /
loud-wrong / missed, and each `exclude` hit as a leak. Read the header of `run.js` for the
definitions; the point of the harness is that "silent-wrong" is the number that costs money.
